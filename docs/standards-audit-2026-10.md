## 2. 이번에 한 호환 수정 (DB 변경 없음)

1. `src/lib/conformance.ts` (새 파일): 항목 단위 적합 요약.
   - 점검자 확정 부적합이 하나라도 있으면 "기준 미충족"이다.
   - 모든 항목을 점검자가 적합·해당 없음으로 확정했을 때만 "충족"이다. 이때도 자체진단이며 인증이 아니다.
   - 그 밖에는 "판정 불가"이고, 비율이나 퍼센트는 쓰지 않는다.
   - 자동 신호는 부적합 확정이 아니고, 자동 문제 미발견은 충족 확정이 아니다.
2. `src/lib/standards-refs.ts` (새 파일): 규칙마다 WCAG 성공기준·ACT 규칙 id 를 **axe-core 메타데이터(tags·actIds)에서만** 가져온다.
   - 자체 규칙(kr-*, ai-*)과 axe 가 연결하지 않은 규칙은 비워 둔다. 대응을 지어내지 않는다.
   - KWCAG 항목 연결과는 섞지 않는다.
3. 통합 묶음 (`bundle.ts`, 형식 `bundle-v2`) 에 추가한 것:
   - 법적·인증 고지 (지정 인증기관의 서면·기술 심사, 인증 표시 사용 불가)
   - WCAG-EM 보고 항목: 점검자, 의뢰 기관, 기준, 판정 대상, 환경, 엔진·AI 설정, 표본 구성
   - **기록하지 못한 정보 목록**: 브라우저 버전, 화면 크기, 보조기술 검사, 사용자 평가, 재현 절차, 무작위 표본, 분기 경로
   - 검사 방법별 기록 수 (보조기술·사용자 평가는 `null` = 기록 없음)
   - 항목 단위 적합 요약, 문제마다 WCAG·ACT 참고와 규칙 종류(WCAG / 모범 사례 / 자체)
4. 묶음 Excel·Word 에 위 항목을 같은 값으로 넣었다. JSON 은 묶음 전체를 그대로 담는다.
5. 회차 JSON(`view-json.ts`)에 `conformance` 필드를 추가했다. 기존 필드는 그대로다.
6. 기존 보고서의 준수율 문구에 "항목 비율 참고값이며, 적합 여부는 모든 해당 항목 충족으로 판단 — 하나라도 부적합이면 미충족" 을 덧붙였다 (KO·JA). 계산은 그대로다.

## 4. 지키는 원칙

- 인증을 주장하지 않는다. 점수·표본 수·인증 보장은 인증기관 심사지침 원문 없이 코드로 만들지 않는다.
- KWCAG 연결과 WCAG·ACT 참고는 분리한다. 연결이 없는 규칙의 대응을 지어내지 않는다.
- 자동 도구는 판정을 돕기만 한다. 최종 판정은 점검자다.
